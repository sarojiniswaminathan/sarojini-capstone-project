# Tailoring Business Agent — MVP

Implements the MVP scope from `plan.md` Section 22: Orders + fractional Inventory
+ Projects + college-schedule-aware Scheduling, wrapped in a conversational agent
that answers the four core queries:

1. What should I work on today?
2. Which order should I prioritise?
3. Do I have enough fabric for this order?
4. What needs to be purchased for order X?

## Design

Matches Section 11's split:

- **Deterministic core** (`agent/inventory.py`, `orders.py`, `scheduling.py`, `priority.py`,
  `planning.py`) — all inventory math, dates, reservations, and priority scoring. No AI
  involved, no API key needed. Fully testable on its own.
- **AI layer** (`agent/tools.py`, `agent.py`, `cli.py`) — Claude decides which of the
  deterministic functions to call (as tools), reasons across the results, and explains
  recommendations in plain language. It never touches the database directly.

The **calendar is the user's actual Google Calendar** — there is no separate
local calendar. `agent/google_calendar.py` reads and writes it directly
(Section 14); `templates/index.html` + `static/calendar.js` (backed by
`calendar_api.py`) is just an in-app *view* onto it, which is what makes
click-to-see-day-info possible. A commitment added via chat or the calendar's
quick-add form is written straight to Google Calendar — there's nothing to
keep "in sync" because there's only ever one copy. Until Google Calendar is
connected, there's simply no commitment data to show (the calendar clearly
says so) — order deadlines (business data from `orders`, always local) still
show up either way.

## Setup

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...   # required only for the chat agent
```

**Google Calendar connection (required for the calendar to show/add anything):**
create an OAuth 2.0 Client ID (type "Web application") in Google Cloud
Console with the Calendar API enabled, add `http://127.0.0.1:8000/` as an
authorized redirect URI (the app root — not a dedicated callback path), and
set in `.env`:

```
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=http://127.0.0.1:8000/
```

Then click "Connect Google Calendar" on the web app once to authorize (the
token is cached in the gitignored `token.json`, refreshed automatically after
that). Without this, the rest of the app (orders, inventory, planning) still
works fully — only the calendar itself has nothing to show.

## Usage

**Test the deterministic core with no API key** (proves the logic is correct on its own):

```bash
python -m agent.demo
```

Runs all four core queries against seeded example data (mirrors the Order #024 /
#031 / #042 scenarios used throughout `plan.md`) and prints the results.

**Run the web app** (calendar + inventory glance strip + chat):

```bash
python -m agent.cli --seed     # first run: reset + load example data into agent/tailoring.db
uvicorn app:app --reload       # then open http://127.0.0.1:8000
```

- **Calendar** (main view) — your actual Google Calendar, once connected;
  click any day to see that day's plan, commitments, and orders due (with
  material shortages flagged), and add a commitment directly from the panel
  or by asking the chat agent — both write straight to Google Calendar.
- **Glance strip** (top) — every material at a glance, color-coded by stock
  level; upload a photo/swatch or make a quick +/- correction per material,
  no separate inventory page.
- **Chat** (floating, bottom-right) — the same conversational agent as
  before; any action it takes refreshes the calendar/strip immediately.

**Or use the terminal chat only** (requires `ANTHROPIC_API_KEY` or `GEMINI_API_KEY`):

```bash
python -m agent.cli --seed     # first run: reset + load example data
python -m agent.cli            # subsequent runs: reuse the existing database
python -m agent.cli --fresh    # start from a completely empty database
```

Example things to ask:
- "What should I work on today?"
- "Which order should I prioritise?"
- "Do I have enough fabric for ORD-024?"
- "What do I need to buy?"
- "I have a new dress order due on the 25th, add it" (agent will ask for missing details)
- "I only got one hour of sewing done today on ORD-024" (log a work session)
- "I found another 0.5m of black cotton" (manual inventory correction)
- "I have a lab exam Friday 2-4pm" (adds a commitment directly to Google Calendar —
  fails with a clear message if it isn't connected yet)

## Data model

SQLite (`agent/tailoring.db`, gitignored, regenerated by `--seed`/`--fresh`). Schema
in `agent/schema.sql`: `materials` (with `photo_path` for the glance-strip
swatch), `material_transactions` (audit trail), `orders`, `projects`,
`project_materials` (planned vs. actual, reserved vs. consumed), `work_sessions`.
There is no local commitments table — the calendar lives entirely in Google
Calendar via `agent/google_calendar.py`. `agent/db.py` migrates existing local
databases created before `photo_path` existed.

Reserved/available material quantities are always *derived* from active
`project_materials` reservations rather than stored directly, so they can't drift.

## What's deliberately not built yet (per Section 22 / post-MVP phases)

Shopping-trip batching/route optimisation, historical project analysis, Apple
Calendar integration, Instagram/marketing automation, customer inspiration PDF
catalogues. See `plan.md` Sections 22–24 for the full phased roadmap.
